# WebZFS 0.90: RC1

After the size of 0.87, this one is going to feel tiny. That's on purpose.

0.90 is the first release candidate. The BETA tag is gone from the caption, and from here to 1.0 the plan is fixes, polish, and testing. So what's in here is a handful of small things that make the stuff that already exists behave better.

### The dashboard was hiding things from you

I went back over the dashboard with one question in mind: if something is wrong with this server, does this page actually tell me?

The answer was "kinda, if you squint", but only if you waved a dead chicken over it.

- A running resilver was displayed as a completed scrub. Which is, as you know, not the same thing.
- Data errors were being collected by the backend and then never shown anywhere. Much Useful. Very Wow. [insert mental random doge meme]
- An unhealthy pool showed you that it was unhealthy, and not a word about why.
- Failed replication jobs and a stopped smartd were only visible if you went to their own pages to check on them.

So now there's an attention strip at the top of the dashboard. It shows up when a pool isn't ONLINE (with the status and action text straight from `zpool status`), when a pool has data errors, or when a resilver is running, with the percent done and time to go. On a healthy system it isn't there at all. No news is good news.

The pool rows now show fragmentation next to capacity, and the scrub state. The age of the last scrub is color coded: green up to 30 days, yellow after that, red after 60, and if you haven't scrubbed in over six months it will pulse at you in bold red until you feel bad about it. I'm half tempted to add an easter egg into the code if you dont scrub for a year, but I havent figured out what that should be yet.  Maybe just remove the entire UI and leave only a big red button that says "Scrub all pool because I haven't because I'm a naughty boy." If you have better creative ideas, file a feature request.
Anyway, since the scrub info with the pool covers everything the old Scrub Status card did, that card is gone.

There's also a new Jobs and Services card that shows whether smartd is running, whether ZED is running (Linux only), any replication runs that failed in the last 24 hours, and any scheduled tasks whose last run failed. The pools card will tell you how your disks looked in the latest health report, and will warn you if you don't have a scrub schedule set up at all.

### Custom vdev properties on older pools

I said in the 0.85 post that I was really happy with the custom vdev properties page. Then someone ran it against a FreeBSD pool that had been around for a while.

The pool level values get stored on the root vdev, and that needs the `vdev_zaps_v2` pool feature. A pool created before that feature existed, and never upgraded, doesn't have anywhere to put them. So the page threw a raw error at you. Even better, in the All Pools view, one pool like that broke the page for every other pool too.

Now each pool gets checked first. A pool that can't do it shows a clear message saying why, and what the upgrade command is, and the rest of your pools carry on working.

### Pool version and upgrade info

That led right into the next thing, which is that there was nowhere in WebZFS to see what feature flags a pool has, or whether an upgrade is available.

The bottom of the pool page now has a "Pool Version and Upgrade" card. It lists the features that an upgrade would enable, with a description of each, the command to run, and extra notes if the pool has a `compatibility` property set or if it's your boot pool.

What it does not have is a button. WebZFS will not run `zpool upgrade` for you. It's a one way process and an upgraded pool may not import on an older system, and if it's your boot pool then your bootloader gets to laugh at you and give you an unbootable system. So this is a decision you should make at a command line, on purpose, and not because something in a web UI was green and looked clickable.

### Small things

- On the Datasets page, the snapshot count is now a link to the Snapshots page filtered to that dataset. And the filtered Snapshots page links back to the dataset. One heads up: the count in the column is that dataset's own snapshots, while the filtered page also includes its children, so the numbers won't match on a parent dataset.
- The shell history log pages were missing their templates. Yes. Again. They existed on my machine. Apparently my Git Master certification from 0.78 has expired.

### What comes next

Testing. Lots of it.

If you've been holding off until things settled down, now is a really good time to install it and try to break it. The dashboard and vdev property changes in particular have had less time on the BSDs than I'd like, so FreeBSD and NetBSD folks, please poke at them and tell me what falls over.

One thing to plan for before 1.0: login restriction is going to be on by default in the final release, and the installers will ask you who the first administrator is. If you haven't already set `RESTRICT_LOGIN=yes`, the [security audit post](./2026-11-11-security-audit-findings-and-fixes.md) explains what it does and why you want it. Better to turn it on now and find out it works for your setup than to find out on upgrade day.

As always, if you find a bug, file a ticket.
